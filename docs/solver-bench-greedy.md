## Planner benchmark: `greedy`

Generated by `make bench PLANNER=greedy` on the seeded catalog (790 TheMealDB + 57 curated
recipes), 20 scenarios per kind, on a 4-vCPU dev container. *planted*: synthetic users with a
known valid plan; *realistic*: user-like profiles; *profiles*: ten fixed user profiles built
through the API's own `make_problem` (two have tight budgets, which the baseline misses: the
only hard rule it doesn't optimise). End to end = build the problem (prefilter) + plan +
validate + shopping list, without database I/O.
